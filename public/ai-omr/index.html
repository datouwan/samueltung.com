V1 contract

Solve one useful problem well.

The first model is intentionally constrained. Every deferred feature is a deliberate reduction in ambiguity, data demand, and debugging time.

Included now

  • Printed Western notation
  • One staff/system, treble clef
  • Mostly monophonic melody
  • Whole through sixteenth notes and rests
  • Dots, common keys and time signatures
  • Accidentals, barlines and basic ties

Deferred on purpose

  • Grand staff and orchestral systems
  • Multiple independent voices
  • Dense chords and tuplets
  • Grace-note-heavy passages
  • Percussion and tablature
  • Handwritten or contemporary notation

System design

Pixels in. MusicXML out.

The neural network predicts a compact musical language. Deterministic software then checks rhythm and syntax before generating verbose MusicXML.

Stabilize the page

Normalize each system onto one fixed canvas and retain its true content width.

Read the staff

Stride-16 Swin features use masked right padding and separable 2D positions.

Decode safely

A Transformer predicts compact notation with legal EOS and corpus-safe loop guards.

Validate music

Check grammar and rhythm, create the score object, then emit reviewable MusicXML.

M8 experiment · 5 systems

Oemer is a useful teacher—not the engine.

A bounded comparison converted Oemer MusicXML into our own score object and token vocabulary. Its strongest results justify borrowing rhythm ideas, while its crashes and latency rule out a direct replacement.

Exact and musically valid transcriptions across all five attempts2/5
Successful MusicXML conversions; two sparse systems crashed3/5
Mean token error rate among the three successful conversions0.023
Five-system CPU wall time with two concurrent workers9.9m
Decision

Keep our proprietary decoder

Use Oemer only as an optional benchmark, high-confidence pseudo-label source, and reference for staff, barline, beam, and beat-repair logic.

What transfers into M8

Measure-duration bookkeeping, visual rhythm cues, and deterministic beat repair. Dataset and checkpoint rights still require separate commercial review.

Operating principles

Accuracy has a provenance.

01Rights-clean by construction

Train from public-domain or permissively licensed symbolic scores, self-render images, and retain source and license metadata.

02Deterministic where possible

Let the model recognize. Let explicit code enforce musical grammar, validate rhythm and generate MusicXML.

03Measure real decoding

Track token error rate, exact sequence match and musical validity on autoregressive output—not loss alone.
