Developing from the iPad

How to drive the home Windows 11 PC — and Claude Code CLI — from an iPad, from anywhere. Terminal first, remote desktop when a GUI is unavoidable.

The stack at a glance

One-time PC setup

All commands in an elevated PowerShell (Run as administrator).

1 · Tailscale

winget install Tailscale.Tailscale
tailscale up          # opens a browser — log in once

Note the machine name it gets (e.g. desktop-xxxx) — that's the address for everything below. The client updates itself and reconnects on boot.

2 · OpenSSH Server

Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Set-Service sshd -StartupType Automatic
Start-Service sshd

# Land in PowerShell instead of cmd on login:
New-Item -Path "HKLM:\SOFTWARE\OpenSSH" -Force | Out-Null
New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell `
  -Value "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" `
  -PropertyType String -Force

Windows adds the OpenSSH-Server-In-TCP firewall rule automatically. Since the PC is only reachable over the tailnet, that's enough.

3 · Remote Desktop

Set-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server" `
  -Name fDenyTSConnections -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"

4 · VS Code tunnel (optional but recommended)

code tunnel service install   # one-time GitHub login

Then vscode.dev in Safari → Remote Tunnels → this machine. Editor, file tree, and a real terminal on the PC — run claude right inside it.

iPad setup

  1. Tailscale (App Store, free) — log in to the same tailnet, flip it on.
  2. Blink Shell (paid, best) or Termius (free) — add host: the PC's tailnet name, user samue. Add a key with ssh-keygen in Blink and append the public key to C:\Users\samue\.ssh\authorized_keys to skip passwords.
  3. Windows App (Microsoft, free) — add PC by tailnet name for RDP.
  4. A hardware keyboard. Non-negotiable — the on-screen keyboard has no Esc or Ctrl.

Daily workflow

ssh samue@<tailnet-name>
cd C:\GitHub\ai-omr-starter
claude

When the iPad sleeps, the SSH session drops but nothing is lost — reconnect and resume:

claude --continue     # jump straight back into the last session
claude --resume       # or pick from recent sessions

There's no tmux on native Windows; --continue is the session persistence. Long autonomous runs keep going on the PC side regardless of the connection.

After an unattended reboot (power cut, Windows Update): Tailscale, SSH, and RDP are services — they come back on their own. But the Cloudflare tunnels (vatutor-omr, gameloop-byom) and their servers start from the Startup folder at logon. So: open the Windows App, RDP in, log in once, done — that logon fires every startup script. Check with Get-Process cloudflared, node.

Next: the Flint 3 front door

Not installed yet — the GL-BE9300 is still in its box. What it changes when it goes in:

Today every remote path needs the PC awake. With the router as the VPN endpoint, the always-on device is the router — the PC can sleep and be woken on demand. The upgrade, when ready:

  1. IP Passthrough on the AT&T gateway (192.168.1.254 → Firewall → IP Passthrough) to the Flint 3's WAN; turn off the gateway's WiFi and let the Flint be the real router. Give the PC a static DHCP lease.
  2. WireGuard Server in the GL Admin Panel, plus GL's built-in DDNS (glddns.com) as the stable endpoint. iPad uses the native WireGuard app (QR-code import, on-demand mode). The BE9300 does ~900 Mbps WireGuard.
  3. Wake-on-LAN: enable "Wake on Magic Packet" in the PC BIOS and NIC properties; wake from the iPad via the router admin panel, a WOL plugin, or the GoodCloud app. Then RDP in and log on — that logon also fires the Cloudflare tunnel startup scripts.
  4. Then simplify: PC-side Tailscale becomes optional (keep as fallback, or move Tailscale onto the router as a subnet router). SSH, RDP, and the VS Code tunnel are unchanged — address the PC by its LAN IP.
